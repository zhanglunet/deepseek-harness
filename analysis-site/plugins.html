插件目录

GitHub 上带 dsh-plugin 话题的全部公开仓库。数据每日自动抓取， 安装命令只在该仓库自己的 package.json 能证明时才显示——猜一条跑不通的命令比不给更糟。

怎么装一个插件

dsh 的插件装进profile——一个 profile 就是一套插件组合。最常见的是给 web profile 加东西：

npx @deepseek-ai/dsh plugin --profile web add <包名或 git 地址>
npx @deepseek-ai/dsh web            # 重启后生效

add 后面接什么，取决于作者怎么发布：

  1. npm 包——直接写包名，例如 add @liustack/modlens。本页在能确认时会直接给出完整命令。
  2. GitHub 仓库——写 github:owner/repo。源码形式的包会在安装时执行 prepare 构建，pnpm ≥10 默认拦截，首次会提示你把它加进 profile 的 pnpm-workspace.yaml 再重试。
  3. 本地目录——add ./my-plugin，路径相对于你执行命令的目录。

技能不是插件

带「技能」标签的多数不用 plugin add，而是把 SKILL.md 放进技能目录即可，例如 ~/.dsh/skills/<名字>/SKILL.md 或项目里的 .agents/skills/。 技能是跨宿主的，同一份内容 Claude Code、Codex 也能用。

数据来源：GitHub 搜索接口的 topic:dsh-plugin，加上逐仓库读取的 package.json。 由 .github/workflows/refresh-ecosystem.yml 每日抓取并提交，Cloudflare Pages 随提交重新发布。

安装命令怎么来的：只有当仓库的 package.json 里同时具备可安装的 npm 名称与 dsh.bundle 声明时，本页才给出完整命令。其余一律标为「安装方式见 README」，不做推测。 GitHub 搜索接口最多返回 1000 条结果，超出部分无法列出，页面会在发生时注明。
